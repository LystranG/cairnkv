OSTEP 持久化部分重读计划

《操作系统导论》第 35–45 章 + 英文版补一章 SSD；分布式（第 46–50 章，含 NFS、AFS）不读

约 5 周 · 每周 3–5 小时 章节号按中文版 勾选状态保存在本机浏览器

怎么读一章（每章都一样）

  1. 读前 5 分钟：翻到本章的「关键问题」框（每章开头附近，如第 42 章"关键问题：考虑到崩溃，如何更新磁盘"），把它抄进笔记，再写下你现在凭记忆的回答，答不出就写"不知道"。
  2. 读：按下表的"精读 / 通读 / 略读"分配精力。精读小节每读完一节就合上书，用两三句话在笔记里复述。
  3. 读后：不看书回答下表里的"带着问题读"，再翻书核对，用另一种颜色补上漏掉的点。
  4. 做作业（标了的章）：跑模拟器，按 README 里的题做 2–3 题。中文版第 42–44 章书里没有作业，去 ostep-homework 仓库对应目录看英文 README。
  5. 写"和 CairnKV 的连接"：一两条就够，写这一章的哪个机制对应引擎里的哪个组件。这一栏最重要。

笔记模板：learning/notes/ostep/_template.md，每章复制一份，命名为 ch42.md 之类。

第 1 周 · 设备与磁盘：顺序写为什么快

  2. 带着问题读：轮询和中断各在什么设备速度下更好？一次 I/O 期间 CPU 在做什么？
  3. 带着问题读：随机 4 KB 读和顺序读的吞吐差多少个数量级？差在寻道、旋转、传输里的哪一项？→ 这就是 LSM"把随机写变成顺序写"的根本动机。
  4. 带着问题读：fail-stop 故障模型假设了什么？到第 44 章时回头对比：真实磁盘的故障比它复杂在哪？

第 2 周 · 文件系统接口与实现

  1. 带着问题读：为什么"删除文件"的系统调用叫 unlink？删除改的是谁的内容？（→ 第 1 课 D4）
  2. 带着问题读：创建一个新文件并写一个块，磁盘上要改哪几个结构？write 为什么能"立即返回"，代价是什么？
  3. 带着问题读：FFS 把"相关的东西放在一起"；LSM 的 SSTable 按键有序存放，算不算同一种思想？

第 3 周 · 崩溃一致性（全书对 CairnKV 最重要的一章）

  1. 带着问题读：① 42.1 里三个写入只完成一部分时，一共有几种崩溃情形，各自的后果是什么？② 数据日志与元数据（有序）日志的写入顺序分别是什么，各省掉了什么？③ 事务提交块为什么要等前面的块写完才写？④ 恢复时为什么"重放"是安全的？→ 对应 CairnKV 的 WAL、确认点与恢复（M1）。

第 4 周 · LFS 与数据完整性

  1. 带着问题读：LFS 是 LSM-Tree 的思想近亲。逐项找对应：写缓冲 ↔ memtable / 组提交；inode 映射 + 检查点区域 ↔ MANIFEST + 当前标记；段清理 ↔ 合并（compaction）；清理成本 ↔ 写放大。哪一项对应不上？为什么？
  2. 带着问题读：校验和放在块里能发现哪些故障，发现不了哪些？"错误的写入"和"丢失的写入"各要额外存什么才能检测？→ 对应块尾 CRC、自测问题 4 与 cairnkv check --full。

第 5 周 · 补一章：中文版没有的 SSD

  1. 带着问题读：闪存为什么不能原地覆写？FTL 的垃圾回收和第 43 章的段清理有什么相同之处？SSD 内部的写放大会和 LSM 的写放大叠加吗？
